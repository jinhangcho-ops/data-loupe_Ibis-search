# 쿼리 화면

[← README](../README.md) · [쿼리 화면](query.md) · [분석 화면](analysis.md) · [수집 화면](collect.md) · [연동](integrations.md) · [설정과 참고](settings.md)

**한 줄 요약**: 엑셀처럼 생긴 데이터에서 "원하는 행만 골라 보고", 합계·평균을 내고, 그래프로 그리는 화면입니다.

쿼리 화면 위쪽에는 탭이 넷 있습니다.

| 탭 | 언제 쓰나 |
|---|---|
| 탐색 | 버튼과 칸만으로 데이터를 찾을 때(처음이면 여기부터) |
| SQL | SQL(데이터를 묻는 문장)을 직접 쓰거나, 질문을 써서 SQL을 만들 때 |
| 지표 | 매출·취소율처럼 자주 보는 숫자를 눌러서 바로 볼 때 |
| 대시보드 | 그려 둔 그래프를 한 화면에 모아 볼 때 |

## 먼저 알아 둘 말

| 말 | 뜻 | 엑셀로 치면 |
|---|---|---|
| 테이블 | 데이터 한 덩어리. 예: 주문 목록 `orders` | 시트 하나 |
| 컬럼 | 세로 한 줄. 예: `금액`, `상태` | 열(A열, B열…) |
| 행 | 가로 한 줄 = 데이터 하나. 예: 주문 한 건 | 행(1행, 2행…) |
| 조건 | 어떤 행만 볼지 정하는 규칙. 예: `상태 = 취소` | 필터 |
| 연결 | 데이터가 있는 파일이나 DB를 프로그램에 붙이는 것 | 파일 열기 |
| DB | 데이터를 담아 두는 프로그램(서버). 회사 데이터는 보통 여기에 있습니다 | — |
| 집계 | 개수·합계·평균처럼 여러 행을 숫자 하나로 줄이는 것 | SUM, AVERAGE |
| 조인 | 두 테이블을 같은 값(예: 고객 번호)으로 옆에 이어 붙이는 것 | VLOOKUP |
| SQL | 데이터를 묻는 표준 문장. 몰라도 탐색 탭은 쓸 수 있습니다 | — |

아래 예시는 설명용으로 지어낸 쇼핑몰 데이터 `shop.duckdb`를 씁니다. 안에는 주문 `orders`(주문번호, 주문일, 고객ID, 상품코드, 매장코드, 수량, 금액, 상태), 고객 `customers`, 상품 `products`, 매장 `stores` 테이블이 있습니다.

## 따라 해 보기

### 예시 1. 취소되지 않은 지난달 주문 보기

1. 첫 화면에서 **[쿼리]** 를 누릅니다. 가운데에 "데이터 연결" 카드가 뜹니다.
2. **폴더나 파일 경로** 칸에 데이터가 있는 폴더(예: `C:\data`)를 넣고 **[찾기]** 를 누릅니다.
3. 아래 목록에서 `shop.duckdb`를 고르고 **[연결]** 을 누릅니다.
4. 오른쪽 "검색 조건" 패널의 **1 데이터** 에서 테이블 `orders`를 고릅니다.
5. **4 기간** 을 눌러 펼치고 `주문일 2026-09-01 ~ 2026-09-30` 을 넣고 Enter를 누릅니다.
6. **5 조건** 을 펼쳐 컬럼 `상태`, 연산자 `!=`(같지 않음), 값 `취소`를 고르고 **[추가]** 를 누릅니다.
7. 패널 아래의 **[검색 실행]** 을 누릅니다.

가운데에 "○○행"과 결과 표가 나옵니다. 표 머리글(예: `금액`)을 누르면 그 순서로 다시 정렬됩니다. 전체를 파일로 받으려면 위쪽 **[저장▾]** → **Excel** 을 누릅니다.

### 예시 2. 고객 이름과 매장 이름을 붙여 보기

주문 표에는 고객ID·매장코드 같은 번호만 있습니다. 이름을 같이 보려면 조인합니다.

1. 예시 1에 이어서 **3 조인** 을 펼칩니다.
2. 종류 `left`, 테이블 `customers`, 키 `고객ID = 고객ID`를 고릅니다. → 고객명이 붙습니다.
3. **[+ 조인 추가]** 를 누르고 `left`, `stores`, `매장코드 = 매장코드`를 고릅니다. → 매장 이름이 붙습니다.
4. **[검색 실행]** 을 누릅니다.

### 예시 3. 매장별 매출을 막대그래프로

1. 결과 위의 **[차트]** 탭을 누릅니다.
2. 윗줄 **X** 에 `매장`을 고릅니다.
3. 아랫줄에서 **Y** `금액`, 집계 `합계`, 종류 `막대`를 고르고 **[그리기]** 를 누릅니다.
4. 매장마다 막대가 하나씩 그려집니다. **[PNG]** 로 그림을 저장하거나 **[대시보드에 추가]** 로 모아 둡니다.

### 예시 4. 자주 쓰는 검색을 저장해 두기

예시 1의 조건을 다음에도 쓰려면 패널 아래 **[저장한 검색]** 을 눌러 이름 칸에 `9월 정상 주문`을 쓰고 **[저장]** 합니다. 다음에는 목록에서 고르기만 하면 조건이 그대로 채워집니다.

### 예시 5. SQL로 직접 묻기

SQL을 조금 안다면 **[SQL]** 탭에서 바로 쓸 수 있습니다.

```sql
SELECT 상태, COUNT(*) AS 주문수, SUM(금액) AS 매출
FROM orders
GROUP BY 상태
```

쓰는 동안 아래에 "✓ 문법 이상 없음"과 "실행하면 약 ○○ KB를 처리합니다"가 나옵니다. **[실행]** 을 누르면 상태별 주문 수와 매출이 나옵니다. SQL을 몰라도 질문 칸에 "상태별 주문 수와 매출"이라고 쓰고 **[SQL 만들기]** 를 누르면 됩니다(LLM 설정이 필요합니다. [질문으로 SQL 만들기](#질문으로-sql-만들기)).

## 연결

연결은 "어떤 데이터를 볼지" 프로그램에 알려 주는 일입니다. 첫 화면에서 [쿼리]나 [분석]을 누르면 가운데에 "데이터 연결" 카드가 뜹니다. 연결하면 고른 화면으로 넘어가고, 이미 연결돼 있으면 카드 없이 바로 넘어갑니다.

![데이터 연결 카드](screen-connect.png)

- 연결을 바꾸려면 위쪽 줄 왼쪽의 연결 이름을 누르거나, 패널 1번 "데이터"의 [연결 바꾸기]를 누릅니다.
- 연결하지 않고 쿼리·분석 화면을 열면 카드가 저절로 뜨고, 연결하기 전에는 닫히지 않습니다.
- 마지막으로 연결한 폴더나 주소·아이디는 다음에 켤 때 칸에 미리 채워져 있습니다.
- 맨 위 [최근 연결]에는 연결에 성공했던 곳이 자주 쓴 순서로 나옵니다(30개까지). 비밀번호는 저장하지 않으므로 DB라면 비밀번호만 다시 넣습니다.

### 내 폴더 파일

내 PC에 있는 데이터 파일을 엽니다. 폴더나 파일 경로를 넣고 [찾기](또는 Enter)를 누릅니다.

| 파일 종류 | 어떤 파일인가 |
|---|---|
| DuckDB (`.duckdb`) | 테이블 여러 개가 들어 있는 데이터베이스 파일 하나 |
| Parquet (`.parquet`) | 큰 데이터를 작고 빠르게 담는 표 파일 |
| CSV (`.csv`) | 쉼표로 칸을 나눈 글자 표. 엑셀에서도 열립니다 |
| JSON (`.json`, `.jsonl`, `.ndjson`) | 웹에서 자주 쓰는 데이터 글자 형식 |
| Excel (`.xlsx`) | 엑셀 파일(첫 시트만 엽니다) |

- **찾을 종류**: 체크한 종류만 찾습니다.
- **하위 폴더까지 찾기**: 켜 두면 폴더 안의 폴더까지 찾습니다(기본). 이름이 `.`으로 시작하는 숨김 폴더는 빼고 찾습니다.
- 경로가 파일 하나면 그 파일만 봅니다.

**DuckDB 파일**은 목록에서 하나를 고르고 [연결]을 누릅니다.

**Parquet·CSV·JSON·Excel 파일**은 여러 개를 함께 열 수 있습니다.

1. 목록에서 [테이블 파일 고르기]를 고르면 찾은 파일이 체크 목록으로 나옵니다.
2. 쓸 파일만 체크합니다([모두 선택]도 있습니다).
3. [연결]을 누릅니다.

파일 하나가 테이블 하나가 되고, 파일 이름이 테이블 이름이 됩니다. 이름이 겹치면 `폴더_이름_확장자`(예: `sub_orders_csv`)로 구분합니다.

**작업 메모리 상한** (DuckDB 파일만)

큰 데이터를 계산하면 PC 메모리를 많이 씁니다. 다른 프로그램이 느려진다면 상한을 정하세요. 제한 없음(기본), 1·2·4·8GB, 또는 [직접 입력] (0.256~1,000GB)을 고르고 다시 [연결]합니다.

- 예: 2천만 행을 집계할 때 제한 없이 2.8GB를 썼고, 2GB로 두면 2.0GB, 1GB로 두면 1.2GB 안에서 끝났습니다. 대신 조금 느려집니다.
- 너무 낮으면 "메모리가 모자랍니다"가 나옵니다. 상한을 올리거나 조건을 좁히세요.
- 넘치는 부분은 임시 폴더(`%TEMP%\ibis_search\`)에 잠시 쓰고, 연결을 끊거나 프로그램을 닫으면 지웁니다.
- 파일(Parquet 등) 연결과 DB 주소 연결에는 적용되지 않습니다. DB 주소로 연결하면 계산은 DB 서버가 합니다.

검색·집계·차트·저장이 끝나면 쓰던 데이터는 메모리에서 비우고 결과만 남깁니다. 그래서 작업이 끝나면 메모리 사용량이 연결 직후 수준으로 돌아갑니다.

### DB 주소

회사 DB처럼 서버에 있는 데이터에 연결할 때 씁니다. 연결 주소(예: `postgres://host:5432/db`)와 아이디, 비밀번호를 넣고 [연결]을 누릅니다. 주소 형식은 DB마다 다르며 [DB별 드라이버](settings.md#db별-드라이버)에 있습니다. 모르면 DB 담당자에게 주소와 읽기 전용 계정을 받으세요.

60초 안에 연결되지 않으면 멈추고 알려 줍니다(주소가 틀렸거나 네트워크가 막혔을 때).

### 연결을 바꾸거나 끊을 때

- 새로 연결하면 이전 연결은 닫히고, 고른 테이블과 조건은 비워집니다.
- 연결에 실패하면 이전 연결이 그대로 남습니다.
- [모두 해제]를 누르면:

| 지금 연결 | 결과 |
|---|---|
| Parquet·CSV·JSON·Excel 파일 | 연결을 끊고 처음 상태로 돌아갑니다 |
| DuckDB 파일, DB 주소 | 연결은 그대로 두고 고른 테이블·조건·결과만 비웁니다 |

## 검색 만들기

오른쪽 "검색 조건" 패널은 1번부터 7번까지 차례로 채우는 순서표입니다. 필요한 칸만 채우면 되고, 단계를 누르면 펼쳐집니다. 접힌 단계에는 무엇을 넣었는지 요약이 보입니다. [검색 실행]을 누르기 전에는 데이터를 읽지 않습니다.

| 단계 | 하는 일 | 예 |
|---|---|---|
| 1 데이터 | 볼 테이블 고르기 | `orders` |
| 2 이어붙이기 | 같은 모양의 테이블을 아래로 붙이기 | 올해 주문 + 작년 주문 |
| 3 조인 | 다른 테이블을 옆으로 붙이기 | 주문에 고객 이름 붙이기 |
| 4 기간 | 날짜 범위 | 9월 한 달 |
| 5 조건 | 어떤 행만 볼지 | 취소 아닌 것 |
| 6 정렬 | 순서 | 금액 큰 것부터 |
| 7 표시 컬럼 | 보일 컬럼만 고르기 | 주문번호, 금액, 상태 |

### 넣고, 고치고, 빼기

기간·조건·정렬·표시 컬럼은 모두 같은 방법으로 다룹니다.

| 하는 일 | 방법 |
|---|---|
| 넣기 | 한 줄을 쓰고 Enter 또는 [추가] |
| 고치기 | 목록의 `✎`를 누르면 그 줄이 입력 칸으로 올라옵니다. 고치고 Enter |
| 빼기 | 목록의 `×` |

잘못 쓰면 그 자리에서 이유를 알려 주고, 비슷한 컬럼 이름이 있으면 "혹시 이것?"처럼 함께 알려 줍니다.

### 테이블

1번 "데이터"에서 볼 테이블을 고릅니다(DB라면 스키마(테이블을 묶는 폴더 같은 것)도). 고르면 컬럼 이름과 타입(숫자·문자·날짜 등)이 아래에 보입니다.

### 이어붙이기

모양이 같은 테이블을 아래로 이어 행을 늘립니다. 예: `orders`(올해)에 `orders_2025`(작년)를 이으면 두 해 주문을 한 번에 검색합니다.

- **left**: 기준 테이블의 컬럼을 모두 남깁니다. 붙이는 테이블에 없는 컬럼은 빈칸이 됩니다.
- **inner**: 모든 테이블에 같이 있는 컬럼만 남깁니다.
- 어느 테이블에서 온 행인지는 자동으로 생기는 `출처` 컬럼에 나옵니다. 조건에도 씁니다(예: `출처 = orders_2025`).
- 기준 테이블에 이미 `출처` 컬럼이 있으면 이어붙일 수 없습니다.

### 조인

다른 테이블을 옆으로 붙입니다. 엑셀의 VLOOKUP과 비슷합니다. 조인마다 종류·테이블·키(같은 값을 가진 컬럼 짝)를 고릅니다. [+ 키]로 키를 더하고, [+ 조인 추가]로 조인을 더합니다.

| 종류 | 뜻 |
|---|---|
| inner | 양쪽에 짝이 있는 행만 남김 |
| left | 왼쪽(지금 테이블)은 모두 남기고, 짝이 없으면 붙는 쪽을 빈칸으로 |
| right | 오른쪽(붙이는 테이블)을 모두 남김 |
| outer | 양쪽 모두 남김 |

처음이면 **left**를 쓰세요. 주문이 빠지지 않습니다.

한 줄로 써도 됩니다: `customers left 고객ID=고객ID` (형식: `테이블 [종류] 왼쪽컬럼=오른쪽컬럼`. 종류를 빼면 inner, 이름이 같으면 이름만, 여러 개는 쉼표로).

### 기간

```
주문일 2026-09-01 ~ 2026-09-30
주문일 2026-09-01 ~
```

형식은 `날짜컬럼 시작 ~ 끝`이고 한쪽은 비워도 됩니다(위 둘째 줄은 "9월 1일부터 지금까지"). 날짜+시간 컬럼에 끝을 날짜로만 쓰면 그날 밤 끝까지 들어갑니다.

### 정렬

```
금액 desc
주문일
```

`desc`는 큰 것부터, `asc`(또는 생략)는 작은 것부터입니다. 먼저 넣은 줄이 우선입니다. 결과 표의 머리글을 눌러도 됩니다.

### 표시 컬럼

```
주문번호, 주문일, 금액, 상태
```

비우면 모든 컬럼을 보여 줍니다. 보이지 않는 컬럼도 조건과 정렬에는 쓸 수 있습니다.

## 조건

조건은 "이런 행만 보여 줘"라는 규칙입니다. 엑셀의 필터와 같습니다.

![조건을 칸으로 넣는 화면](screen-conditions.png)

### 넣는 방식

"5 조건"에서 두 방식 중 편한 것을 고릅니다. 어느 방식으로 넣어도 같은 목록에 쌓입니다.

**칸으로 선택** (처음이면 이것)

1. 컬럼을 고릅니다(예: `상태`).
2. 연산자를 고릅니다(예: `=`). 컬럼 종류에 맞는 것만 보입니다.
3. 값을 넣고 [추가]를 누릅니다. 문자 컬럼은 [목록]을 누르면 그 컬럼에 실제로 있는 값(최대 200개)을 불러와 고를 수 있습니다.

**한 줄 입력** (빠르게 쓰고 싶을 때)

```
금액 >= 100000
상태 = 완료
금액 between 10000 50000
상태 in 완료, 배송 중
상태 except 취소
고객명 like 김
메모 is not null
상태 = 취소 or 금액 >= 300000
```

### 연산자

| 연산자 | 뜻 | 예 |
|---|---|---|
| `=`, `!=` | 같다, 다르다 | `상태 = 완료` |
| `>=`, `<=`, `>`, `<` | 크다·작다 (숫자, 날짜) | `금액 >= 100000` |
| `between 값1 값2` | 값1 이상 값2 이하 | `금액 between 10000 50000` |
| `in 값1, 값2` | 이 중 하나 | `상태 in 완료, 배송 중` |
| `except 값1, 값2` | 이것들을 빼고 | `상태 except 취소` |
| `like 값` | 이 글자가 들어 있음(대소문자 무시) | `고객명 like 김` |
| `is null`, `is not null` | 비어 있다, 비어 있지 않다 | `메모 is null` |

`!=`와 `except`는 값이 비어 있는 행도 함께 뺍니다.

구조(묶음) 컬럼 안의 값은 점으로 씁니다(예: `user.name = 가람`). 정렬·표시 컬럼에도 같습니다. 목록 컬럼 안의 값으로 거르는 것은 아직 안 됩니다(`is null`만).

### and와 or

조건이 여러 개면 기본은 **and**(모두 만족)입니다. 목록에서 조건 오른쪽의 [and]를 누르면 [or](하나만 만족해도)로 바뀝니다. or로 이어진 조건은 왼쪽에 세로선으로 묶여 보입니다.

| 목록 | 뜻 |
|---|---|
| `A` [and] `B` [and] `C` | A이고 B이고 C |
| `A` [or] `B` [and] `C` | (A 또는 B)이고 C |
| `A` [and] `B` [or] `C` | A이고 (B 또는 C) |

예: "취소이거나 30만 원 이상인 주문 중에서 9월 것" → `상태 = 취소` [or] `금액 >= 300000` [and] 기간 9월.

여기서는 **or를 먼저 묶습니다**(세로선이 실제 묶음). 실제로 어떻게 보내지는지는 [SQL 보기]로 확인할 수 있습니다.

### 따옴표

값 안에 `or`나 쉼표가 있으면 따옴표로 감쌉니다.

```
상품명 = 'black or white'
고객명 in 'Kim, Lee', Park
```

칸으로 넣을 때는 프로그램이 알아서 감쌉니다. 따옴표가 실제로 들어 있는 값을 찾으려면 입력칸 아래 [따옴표로 값 감싸기]를 끄고 추가합니다.

## 검색하기

패널 아래쪽의 [검색 실행]과 [저장한 검색]은 늘 보이고, 그 바로 위에 [처리 용량](#처리-용량)이 나옵니다.

### 검색

결과 아래 줄의 "쪽당 … 행"(1~10,000, 기본 20)을 정하고 [검색 실행]을 누릅니다. 화면에는 쪽 단위로 보이고, 전체는 [저장▾]으로 받습니다.

### 처리 용량

[검색 실행] 위에 "실행하면 약 1.2 GB를 처리합니다"처럼 나옵니다. 데이터를 실제로 읽지 않고 미리 센 값입니다. **읽은 양만큼 요금이 나오는 DB(BigQuery 등)에서 실행 전에 비용을 가늠할 때** 씁니다. 조건이나 SQL을 바꾸면 다시 셉니다.

| 연결 | 세는 방법 | 정확도 |
|---|---|---|
| BigQuery | Google이 주는 미리 보기(dry run, 요금 없음) | 정확(요금 기준과 같음) |
| Parquet 파일 | 파일 안 정보에서 읽을 컬럼의 크기 | 거의 정확 |
| CSV·JSON·Excel 파일 | 파일 크기 | 최대치 |
| DuckDB 테이블 | 행 수 × 컬럼 크기 | 추정 |
| Postgres | DB 통계 | 추정(통계가 없으면 알 수 없음) |
| 그 밖의 DB | — | 알 수 없음 |

- 읽는 컬럼만 셉니다. 표시 컬럼을 고르면 그만큼 줄어듭니다. 요금이 걱정되면 필요한 컬럼만 고르세요.
- 조건으로 건너뛰는 부분은 BigQuery만 반영합니다. 나머지는 테이블 전체를 읽는다고 보고 셉니다.

### 전체 행 수 세기

켜 두면 조건에 맞는 전체 행 수도 함께 셉니다. 끄면 DB에 보내는 조회가 한 번 줄고(두 번 → 한 번), 결과 제목에 전체 행 수가 빠집니다. 읽은 양만큼 요금이 나오는 DB에서는 끄고 쓰세요.

### 검색 저장과 불러오기

테이블·조인·기간·조건·정렬·표시 컬럼·행 수를 이름을 붙여 저장합니다. 연결 정보는 담지 않아서 연결을 바꿔도 남습니다(100개까지).

| 하는 일 | 방법 |
|---|---|
| 저장 | 이름을 쓰고 [저장]. 이름을 비우면 지금 고른 검색에 덮어씁니다 |
| 불러오기 | 목록에서 고릅니다. 조건만 채우고 검색은 하지 않습니다. 자주 쓴 것이 위에 옵니다 |
| 삭제 | 고르고 [삭제] |

지금 연결에 없는 테이블·컬럼이 든 검색은 불러오지 않고 이유를 알려 줍니다.

## 결과

### 결과 표

| 하는 일 | 방법 |
|---|---|
| 몇 행인지 보기 | 표 위에 큰 글씨로 "286행 중 1–20행 · 상태 != 취소"처럼 나옵니다 |
| 이 쪽에서 글자 찾기 | 맨 위 "결과 안에서 찾기"에 쓰면 지금 보이는 행 중 그 글자가 든 행만 남기고 강조합니다 |
| 다음 쪽 | 아래 [이전] [다음]. 정렬을 정해 두어야 쪽을 넘길 때 순서가 흔들리지 않습니다 |
| 정렬 바꾸기 | 머리글을 누르면 작은 순, 한 번 더 누르면 큰 순 |
| 어느 테이블 컬럼인지 | 조인으로 붙은 컬럼은 머리글 아래에 원래 테이블 이름이 작게 나옵니다 |
| 긴 글 보기 | "글자 … 까지"(기본 40, 0은 전부)만큼 보이고, 마우스를 올리면 전체가 보입니다 |
| 묶음 값 보기 | `{name: 가람, age: 30}`, `[a, b]` 같은 묶음 값은 마우스를 올리거나 눌러서 펼칩니다 |
| DB로 보낼 문장 보기 | [SQL 보기]. 실행하지는 않습니다(파일 연결은 볼 수 없음) |

### 결과 저장

위쪽 [저장▾]에서 형식을 고르면 화면에 보이는 쪽과 상관없이 **조건에 맞는 전체 행**을 저장합니다.

| 형식 | 이럴 때 |
|---|---|
| Excel | 바로 열어 볼 때. 1,048,575행까지 |
| CSV | 다른 프로그램에 넣을 때. Excel에서 열어도 한글이 깨지지 않습니다 |
| Parquet | 아주 크거나 다시 이 프로그램으로 열 때 |

CSV·Excel에서는 `=`, `+`, `-`, `@`로 시작하는 글자 값 앞에 `'`를 붙입니다. 엑셀이 그 값을 수식으로 실행하지 않게 하려는 안전장치입니다.

### 전처리로 보내기

검색 결과를 분석 화면에서 정리하고 싶을 때 결과 아래 [전처리로 보내기]를 누릅니다.

1. 저장할 위치와 이름을 묻습니다.
2. 조건에 맞는 전체 행을 그 위치에 Parquet 파일로 저장합니다.
3. 연결이 그 파일로 바뀌고, 분석 화면의 전처리 탭이 그 테이블로 열립니다.

원래 DB를 다시 보려면 다시 연결하세요.

### 집계

결과 위 [집계] 탭에서 [집계 계산]을 누르면 컬럼마다 개수, 빈 값 수, 서로 다른 값 수, 최소·최대(숫자·날짜), 평균(숫자)을 계산합니다. 데이터를 처음 받았을 때 "어떤 값들이 있나" 훑어보기 좋습니다.

- [집계할 컬럼 추가]로 일부 컬럼만 고를 수 있습니다(큰 테이블에서 더 빠름).
- 표 아래 [PNG] [JPG]로 표 전체를 그림으로 저장합니다. 그 옆에서 흰 배경(라이트)·어두운 배경(다크)을 고릅니다.

### 여러 계열 겹치기

예: "매장별 매출(막대)과 평균 수량(점선)을 한 그래프에"

1. 아랫줄: Y `금액`, `합계`, `막대`, `왼쪽 축` → [계열 추가]
2. 아랫줄: Y `수량`, `평균`, `선`, `점선`, `오른쪽 축` → [계열 추가]
3. [그리기]

매출(수백만)과 수량(몇 개)처럼 크기가 많이 다른 값은 한쪽을 오른쪽 축에 두어야 둘 다 잘 보입니다. 계열이 둘 이상이면 범례가 나옵니다.

### 값별로 나누기

[나누기]에 컬럼을 고르면 그 값마다 계열이 생깁니다. 예: X `주문일`, 나누기 `상태` → 완료·배송 중·취소가 선 세 개로. 값이 많으면 많은 순으로 8개까지 그립니다.

### 세로축 범위

계열 목록 아래 최소·최대 칸에 값을 넣으면 세로축이 그 범위로 고정됩니다. 비우면 자동입니다.

### 비율

[비율 자동]이면 그룹이 적을 때는 정사각형, 많을수록 넓어져 25개 이상이면 16:9가 됩니다.

## SQL 직접 쓰기

[SQL] 탭에서는 SQL을 직접 써서 실행합니다. 탐색의 칸으로 만들기 어려운 복잡한 질문에 씁니다. SQL을 몰라도 [질문으로 SQL 만들기](#질문으로-sql-만들기)를 쓸 수 있습니다.

![SQL 탭](screen-sql.png)

1. 가운데 편집기에 SQL을 씁니다. 오른쪽 [테이블] 칩을 누르면 테이블 이름이 들어갑니다.
2. 잠깐 멈추면 아래에 검사 결과가 나옵니다.
   - ✓ 문법 이상 없음 + 처리 용량
   - ✕ "3줄 15칸: 닫는 괄호 ')'가 필요합니다"처럼 틀린 자리. 편집기 테두리가 빨개집니다.
   - [검사]를 누르면 컬럼 이름까지 확인합니다(데이터는 읽지 않음).
3. [실행](또는 Ctrl+Enter)을 누르면 결과가 [받을 행] 수(기본 1,000)까지 표로 나옵니다.
4. 전체 결과는 [결과 저장▾]에서 CSV·Excel·Parquet으로 받습니다.

**예시**

```sql
-- 매장별 매출 상위 순
SELECT s.매장, SUM(o.금액) AS 매출
FROM orders o JOIN stores s ON o.매장코드 = s.매장코드
WHERE o.상태 <> '취소'
GROUP BY s.매장
ORDER BY 매출 DESC
```

**안전장치**: 데이터를 읽기만 하는 문장(SELECT) 하나만 실행합니다. `DELETE`(지우기), `UPDATE`(고치기), `DROP`(테이블 없애기)처럼 데이터를 바꾸는 문장이나 `;`로 여러 문장을 이으면 실행하지 않고 알려 줍니다. 실수로 데이터를 망가뜨릴 걱정이 없습니다.

[저장한 SQL]에 이름을 붙여 저장해 두고 다시 불러옵니다(연결 정보는 저장하지 않음).

### 질문으로 SQL 만들기

편집기 위 질문 칸에 우리말로 쓰고 [SQL 만들기](또는 Enter)를 누르면 AI(LLM)가 SQL을 만들어 편집기에 넣어 줍니다.

**예**: "9월에 매장별로 취소되지 않은 주문의 매출 합계를 큰 순으로" → [SQL 만들기] → 편집기에 SQL이 들어오고 아래에 검사 결과가 나옴 → 확인하고 [실행].

**처음 한 번 설정**: AI 회사의 API 키가 필요합니다. 메모장으로 아래처럼 쓴 파일(예: `C:\keys\llm.env`)을 만들고, 질문 칸 아래 LLM 경로 칸에 그 경로를 넣고 [읽기]를 누릅니다.

```
LLM_PROVIDER=anthropic
LLM_API_KEY=발급받은 키
LLM_MODEL=모델 이름
```

| 항목 | 뜻 |
|---|---|
| `LLM_PROVIDER` | `anthropic`(Claude) 또는 `openai`(OpenAI, Azure, 사내 AI 게이트웨이, 내 PC의 Ollama처럼 같은 형식을 쓰는 곳) |
| `LLM_API_KEY` | 그 회사에서 발급받은 키 |
| `LLM_MODEL` | 쓸 모델 이름 |
| `LLM_BASE_URL` | (선택) 회사 기본 주소가 아닐 때. `https://`만 되고, 내 PC(`http://localhost`)만 예외입니다 |
| `LLM_MAX_TOKENS` | (선택) 답의 최대 길이. 기본 1024 |

- 프로그램에는 파일 경로만 저장하고, 키는 물을 때마다 그 파일에서 읽습니다.
- 경로를 비우고 [읽기]를 누르면 AI를 쓰지 않습니다. 그동안은 바깥으로 아무것도 보내지 않습니다.

**AI에게 무엇이 가나요?** [프롬프트 보기]로 그대로 볼 수 있습니다. 테이블·컬럼 이름과 종류, [데이터 명세서](analysis.md#데이터-명세서)의 설명, [지표](#지표) 정의, 그리고 질문입니다. **실제 데이터 값(고객 이름, 금액 등)은 보내지 않습니다.**

**AI가 만든 SQL은 자동으로 실행하지 않습니다.** 편집기에 넣고 위와 같은 검사(읽기만 하는 문장인지, 있는 테이블인지)를 거칩니다. 확인하고 [실행]을 누르는 것은 사람입니다.

### 가상 테이블

자주 쓰는 SQL에 이름을 붙여 테이블처럼 씁니다. DB에는 아무것도 만들지 않고, 이 프로그램 안에서만 쓰는 별명입니다.

**예**: "8만 원 이상 주문"을 자주 본다면

1. 편집기에 `SELECT * FROM orders WHERE 금액 >= 80000` 을 씁니다.
2. 오른쪽 [가상 테이블]의 이름 칸에 `큰주문`을 쓰고 [지금 SQL로]를 누릅니다.
3. 이제 `SELECT * FROM 큰주문`처럼 쓰거나, 탐색 탭의 테이블 목록에서 `큰주문`을 골라 조건·차트에 그대로 씁니다.

- Parquet 파일 하나를 가상 테이블로 쓰려면 경로를 넣고 [Parquet으로]를 누릅니다(DuckDB·파일 연결에서만).
- 연결마다 따로 저장됩니다. 저장할 때 실제로 읽어 보고, 안 되면 이유를 알려 줍니다.
- [정의]로 불러와 고쳐서 같은 이름으로 다시 저장하면 바뀝니다. ×로 지웁니다.

## 지표

[지표] 탭에서는 "매출", "취소율", "객단가"처럼 자주 보는 숫자를 **눌러서 바로** 봅니다. 지표를 어떻게 계산할지는 파일에 한 번 적어 둡니다.

**예: 지표 파일 만들기** (메모장으로 `C:\data\metrics.yaml` 저장)

```yaml
metrics:
  매출:
    description: 취소 아닌 주문 금액 합계
    numerator: {agg: sum, column: 금액, where: "상태 != 취소"}
  취소율:
    description: 전체 주문 중 취소 비율
    format: percent
    numerator: {agg: count, where: "상태 = 취소"}
    denominator: {agg: count}
  객단가:
    description: 완료 주문 한 건당 금액
    numerator: {agg: sum, column: 금액, where: "상태 = 완료"}
    denominator: {agg: count, where: "상태 = 완료"}
```

| 항목 | 뜻 |
|---|---|
| `numerator` | 분자(위에 올 숫자) |
| `denominator` | 분모(아래에 올 숫자). 없으면 분자 그대로. 분모가 0이면 오류 대신 "—" |
| `agg` | 계산 방법: `count`(개수), `sum`(합계), `mean`(평균), `min`(최소), `max`(최대), `nunique`(서로 다른 값 개수, 예: 고객 수) |
| `column` | 계산할 컬럼(개수는 없어도 됨) |
| `where` | 이 계산에만 거는 조건. 탐색의 조건과 같은 모양. 여러 개는 `["조건1", "조건2"]`(모두 만족) |
| `format: percent` | 화면에 %로 보입니다(0.25 → 25%) |
| `description` | 목록에 보일 설명 |

파일에는 계산식(프로그램 코드)을 쓰지 않습니다. 위 항목만 읽고, 모르는 항목이 있으면 읽지 않고 이유를 알려 줍니다.

**쓰는 순서**

1. [탐색]에서 테이블(예: `orders`)과, 필요하면 기간·조건을 고릅니다. 지표는 이 데이터 위에서 계산합니다.
2. [지표] 탭 오른쪽에 지표 파일 경로를 넣고 [읽기]를 누릅니다(파일을 고친 뒤에도 [읽기]).
3. 목록의 지표를 누르면 바로 계산됩니다. 예: "취소율 25%". 자주 누른 지표가 위로 올라옵니다.
4. [나누기]에 `매장`을 고르고 다시 누르면 매장별 취소율이 그래프와 표로 나옵니다(앞 50개).
5. [대시보드에 추가]로 그래프를 대시보드에 넣습니다. 대시보드를 다시 열면 그때의 지표 파일로 다시 계산합니다.
