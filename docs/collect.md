# 수집 화면

[← README](../README.md) · [쿼리 화면](query.md) · [분석 화면](analysis.md) · [수집 화면](collect.md) · [연동](integrations.md) · [설정과 참고](settings.md)

**한 줄 요약**: 인터넷에 있는 데이터(웹 API, 파일, 웹페이지)를 받아 내 PC에 표 파일로 저장하고, 필요하면 회사 DB나 Kafka에 넣어 주는 화면입니다. 정해 둔 시간에 저절로 돌릴 수도 있습니다.

## 먼저 알아 둘 말

| 말 | 뜻 |
|---|---|
| API | 프로그램끼리 데이터를 주고받는 창구. 주소로 요청하면 데이터(대개 JSON)를 돌려줍니다 |
| JSON | 데이터를 글자로 적는 형식. `{"name": "가람", "price": 1000}` 같은 모양 |
| API 키 / 토큰 | API를 쓸 수 있다는 출입증. 비밀번호처럼 다뤄야 합니다 |
| env 파일 | API 키 같은 비밀 값을 `이름=값` 모양으로 적어 두는 메모장 파일 |
| 쪽 넘기기 | 데이터가 많으면 API가 여러 쪽으로 나눠 줍니다. 1쪽, 2쪽…을 차례로 받는 것 |
| 사용 한도 | API가 정한 "1분에 몇 번까지" 같은 제한 |
| 적재 | 받은 데이터를 DB 테이블이나 Kafka에 넣는 것 |
| Kafka | 데이터를 실시간으로 흘려보내는 회사 시스템. 메시지를 "토픽"에 넣습니다 |

## 화면 생김새

오른쪽 "수집 설정" 패널에 단계가 있고(구성 → 받는 방식 → env 파일 → 쪽 넘기기 → 받는 속도 → 사용 한도 → 저장), 누르면 펼쳐집니다. 가운데에는 요청·응답·적재·실행·예약·업로드 기록·실행 기록 카드가 있습니다. 패널 아래 [예상 확인]·[시작]이 실행 버튼입니다.

| 받는 방식 | 이럴 때 |
|---|---|
| API | 서비스가 데이터 주소(API)를 제공할 때. 여러 쪽을 차례로 받습니다 |
| 파일 주소 | 인터넷에 CSV·Parquet·JSON 파일이 올라와 있을 때 |
| 웹페이지 | API가 없고 웹 화면에만 보일 때. 받을 값을 마우스로 눌러 지정합니다 |

## 따라 해 보기

### 예시 1. API에서 상품 목록 받기

어떤 쇼핑몰 API 문서에 이런 예시가 있다고 합시다.

```
curl 'https://api.example.com/v1/items?page=1' -H 'Authorization: Bearer abc123'
```

1. 메모장으로 `C:\keys\shop.env` 파일을 만들고 `SHOP_KEY=abc123` 한 줄을 적어 저장합니다.
2. 수집 화면 가운데 **[요청 예시 붙여 넣기]** 에 위 curl을 그대로 붙여 넣고 **[읽기]** 를 누릅니다. 주소·헤더 칸이 채워집니다.
3. 프로그램이 `Authorization` 헤더가 비밀 값이라고 알려 줍니다. **env 파일** 단계에 `C:\keys\shop.env`를 넣고 [읽기] → 그 줄에서 `SHOP_KEY`를 고르고 **[env 이름으로 바꾸기]** 를 누릅니다. 이제 키는 화면·구성에 남지 않고 `Bearer {env:SHOP_KEY}`로 바뀝니다.
4. 주소의 `page=1`을 `page={page}`로 고치고, **쪽 넘기기** 단계에서 "쪽 번호"를 고릅니다.
5. **[시험 보내기]** 를 누르면 첫 쪽 응답이 트리로 나옵니다. 상품 목록(`items`)을 눌러 **[기록 위치로]** 를 누르면 앞 20행 미리보기가 나옵니다.
6. **저장** 단계에서 [저장 위치 고르기]로 `C:\data\items.parquet`을 정합니다.
7. **[예상 확인]** 으로 요청 수를 보고 **[시작]** 을 누릅니다. 끝나면 **[쿼리로 열기]** 로 바로 봅니다.

### 예시 2. 매일 아침 9시에 저절로 받기

1. 예시 1을 마친 상태에서 [구성] 단계에 `상품 목록`이라고 쓰고 [저장]합니다.
2. **[예약]** 카드에서 구성 `상품 목록`, 주기 `매일`, 시각 `09:00`을 고릅니다.
3. PC를 켜 두기만 할 거라면 [Windows 예약 작업으로 등록]을 체크합니다(프로그램을 꺼도 돕니다).
4. **[예약 저장]** 을 누릅니다. 실패하면 알림을 받도록 [알림]에 보낼 곳(예: Slack)을 고를 수 있습니다.

### 예시 3. 웹페이지에서 상품 이름과 가격 받기

1. **받는 방식** 에서 [웹페이지]를 고르고 주소를 넣고 [브라우저 열기]를 누릅니다. 수집용 창이 따로 뜹니다.
2. 로그인이 필요하면 수집용 창에서 직접 로그인합니다.
3. **[값 고르기]** 를 누르고 수집용 창에서 첫 상품의 이름을 누릅니다. 같은 모양의 상품들이 옅게 표시됩니다.
4. 같은 상품의 가격을 누르면 컬럼이 하나 더 생깁니다.
5. 여러 쪽이면 [다음 버튼 고르기]를 누르고 사이트의 [다음] 버튼을 누릅니다.
6. [고르기 끄기] → [미리보기]로 확인하고, 저장 위치를 정해 [시작]합니다.

### 예시 4. 받은 데이터를 회사 DB에 넣고, 나중에 그것만 지우기

1. **[적재]** 카드에서 [DB 테이블]을 고르고 연결·테이블 이름(`items`)·방식(덧붙이기)을 정합니다.
2. **[적재 ID 컬럼 넣기]** 를 켭니다. 행마다 이번 적재의 번호가 붙습니다.
3. [시작]하면 받기가 끝난 뒤 DB에 넣습니다.
4. 나중에 잘못 넣은 걸 알았다면 **[업로드 기록]** 카드에서 그 줄을 누릅니다. `DELETE FROM "items" WHERE "_ibis_load_id" = '…'` 같은 지우기 명령이 나옵니다. 이 명령을 DB 담당자와 확인하고 실행하면 그 적재분만 정확히 지워집니다(프로그램이 직접 지우지는 않습니다).

## 수집

### 요청 넣기

API 문서의 요청 예시를 [요청 예시 붙여 넣기]에 그대로 붙여 넣고 [읽기]를 누르면 방식·주소·쿼리·헤더·본문 칸이 채워집니다. 칸에서 직접 고쳐도 됩니다.

| 붙여 넣을 수 있는 모양 | 예 |
|---|---|
| curl 명령 | `curl 'https://api.example.com/v1/items?page=1' -H 'Accept: application/json'` |
| HTTP 요청 글 | 첫 줄 `GET /v1/items?page=1 HTTP/1.1`, 다음 줄부터 `Host:` 등, 빈 줄 뒤에 본문 |
| JSON | `{"method": "GET", "url": "https://…", "headers": {…}}` |

읽지 못한 옵션은 따로 보여 줍니다. 붙여 넣은 글은 저장하지 않습니다.

### 비밀 값과 env 파일

API 키나 토큰은 구성에 그대로 저장하지 않고, env 파일에 넣어 **이름으로** 씁니다. 다른 사람에게 구성을 보여 줘도 키가 새지 않습니다.

1. 메모장으로 env 파일(`API_KEY=값`처럼 한 줄에 하나)을 만들고, [env 파일]에 경로를 넣어 [읽기]를 누릅니다. 이름만 보이고 값은 안 보입니다.
2. [읽기]가 비밀처럼 보이는 값(Authorization·Cookie 헤더, 이름에 key·token·secret·password가 든 값, 주소 안 비밀번호)을 찾아 줍니다.
3. 줄마다 env 이름을 고르고 [env 이름으로 바꾸기]를 누르면 그 자리에 `{env:API_KEY}`가 들어갑니다.
4. 비밀이 아닌 값이면 ×로 빼도 됩니다(Authorization·Cookie와 주소 안 비밀번호는 못 뺌).

비밀처럼 보이는 값이 남아 있으면 저장·시험·시작을 하지 않습니다. 값은 저장하지 않고 화면·오류 문구에서 `●●●`로 가립니다.

### 자리 표시

주소·쿼리·헤더·본문 어디에나 아래 "빈칸"을 넣으면 보낼 때 값으로 바뀝니다.

| 자리 | 바뀌는 값 | 예 |
|---|---|---|
| `{env:이름}` | env 파일의 값 | `Bearer {env:API_KEY}` |
| `{page}` `{offset}` `{cursor}` | 쪽 넘기기 값 | `?page={page}` |
| `{today:%Y%m%d}` | 오늘 날짜 | `?date={today:%Y%m%d}` → `?date=20261020` |
| `{now:%Y-%m-%dT%H:%M:%S}` | 지금 시각 | |

### 응답 지정

[시험 보내기]를 누르면 첫 쪽만 한 번 보내고, 실제로 보낸 요청(비밀은 가림)과 응답을 보여 줍니다. JSON 응답은 트리로 보이며, 값을 눌러 쓰임을 정합니다.

| 누른 것 | 고를 수 있는 것 |
|---|---|
| 목록 | [기록 위치로]: 이 목록의 항목 하나가 결과의 한 행 |
| 항목 안의 값 | [컬럼으로 넣기] / [컬럼에서 빼기], 이름 바꾸기 |
| 아무 값 | [다음 커서 위치], [다음 주소 위치], [전체 수 위치] |

- 컬럼을 하나도 고르지 않으면 모든 값을 컬럼으로 만듭니다(안에 묶인 값은 `price.won`처럼 풀어서).
- 지정할 때마다 앞 20행 미리보기가 나옵니다.

### 쪽 넘기기

| 종류 | 요청에 넣을 자리 | 다음 쪽은 |
|---|---|---|
| 없음 | | 한 번만 받음 |
| 쪽 번호 | `{page}` | 1, 2, 3…처럼 1씩 늘림 |
| offset | `{offset}` | 0, 100, 200…처럼 정한 만큼 늘림 |
| 커서 | `{cursor}` | 응답에 들어 있는 "다음 쪽 표시"를 넣음 |
| 다음 주소 | | 응답에 들어 있는 다음 쪽 주소로 보냄 |

빈 쪽이 오거나, 같은 다음 쪽 표시가 다시 오거나, 전체 수만큼 받았거나, 최대 쪽 수에 닿으면 멈춥니다. API 문서에 어느 방식인지 보통 적혀 있습니다.

### 받는 속도

서버에 부담을 주지 않도록 천천히, 실패하면 다시 보냅니다.

| 칸 | 뜻 |
|---|---|
| 동시 수 | 한꺼번에 보내는 요청 수(기본 2) |
| 간격(초) | 요청 사이 최소 간격(기본 1초) |
| 다시 시도 횟수 | 실패한 요청을 다시 보내는 횟수(기본 5) |
| 시간 초과(초) | 응답을 기다리는 시간(기본 30초) |

- "너무 많이 보냄"(429)이 오면 저절로 속도를 반으로 줄이고 서버가 쉬라는 만큼 쉽니다(15분이 넘으면 멈춤).
- 인증 오류(401·403)면 바로 멈추고 키를 확인하라고 알립니다.
- 실패가 20번을 넘으면 멈춥니다.

### 사용 한도

API가 정한 한도(예: "분당 60번, 하루 10,000번")를 묶음으로 저장해 두고 구성에서 고릅니다. 같은 키를 쓰는 구성들이 같은 묶음을 고르면 사용량을 함께 셉니다.

| 칸 | 뜻 |
|---|---|
| 초당·분당·시간당·하루 | 보낼 수 있는 요청 수(비우면 제한 없음) |
| 동시 수, 최소 간격 | 이 묶음을 쓰는 동안의 상한 |
| 하루 초기화 시각, 시간대 | 하루 횟수가 0으로 돌아가는 때(기본 한국 시간 0시) |
| 여유분(%) | 한도보다 이만큼 덜 씀(안전하게) |

- [시험 보내기], 다시 보낸 요청, 실패한 요청도 셉니다. 프로그램을 껐다 켜도 이어서 셉니다.
- 하루 한도에 닿으면 받은 데까지 남기고 멈춥니다. 다음 날 다시 시작하면 이어 받습니다.
- 사용량 파일이 망가지면 안전하게 "다 쓴 것"으로 보고 멈춥니다. 그때는 [사용량 초기화]를 누릅니다.

### 파일 주소

- 서버가 나눠 받기를 지원하면 여러 조각(1~16, 기본 4)으로 동시에 받아 빠릅니다.
- 한글이 깨지는 옛날 CSV(CP949)는 자동으로 알아보고 바꿉니다.
- 다 받으면 크기와 실제로 표로 열리는지 확인합니다.

### 웹페이지

1. [받는 방식]에서 [웹페이지]를 고르고 주소를 넣고 [브라우저 열기]를 누릅니다.
2. 로그인이 필요하면 수집용 창에서 직접 로그인합니다(프로그램은 비밀번호를 다루지 않음).
3. [값 고르기]를 누르고 첫 항목의 값을 누릅니다. 같은 모양의 항목이 옅게 표시됩니다.
4. 같은 항목 안의 다른 값을 누를 때마다 컬럼이 늘어납니다. 글자 대신 링크 주소 같은 속성도 고를 수 있습니다.
5. 여러 쪽이면 [다음 버튼 고르기]로 [다음] 버튼을 지정합니다.
6. [고르기 끄기] → [미리보기]로 확인합니다.

| 쪽 넘기기 | 방식 |
|---|---|
| 없음 | 지금 쪽만 |
| 다음 버튼 | 지정한 버튼을 눌러 넘김 |
| 주소의 `{page}` | 주소 안 쪽 번호를 1씩 늘림 |
| 스크롤 | 끝까지 내려서 더 불러옴(무한 스크롤 사이트) |

- 늦게 나타나는 목록도 기다렸다가 받습니다(최대 [기다리기]초).
- 첫 쪽부터 0건이면 페이지가 바뀌었거나 로그인이 풀렸을 수 있다고 알립니다.
- [robots.txt 지키기](기본 켜짐): 사이트가 "가져가지 마세요"라고 정해 둔 주소는 열지 않습니다. 끄면 사이트 이용 약관을 직접 확인하세요.
- 쪽 하나를 여는 것을 사용 한도 1번으로 셉니다.
- [실행 중 수집용 창 보이기]를 끄면 창을 숨긴 채 받습니다.
- 팝업으로 로그인하는 사이트나, iframe·그림자 DOM 안의 값은 다루지 못할 수 있습니다.
- 수집용 창의 로그인 정보는 `%APPDATA%\ibis_search\browser\`에만 남습니다. [로그인 정보 지우기]로 지웁니다.

### 저장과 실행

1. [저장 위치 고르기]로 결과 파일(Parquet 또는 CSV)을 정합니다. 중복 기준 컬럼을 넣으면 같은 값은 처음 하나만 남깁니다.
2. [예상 확인]: 예상 요청 수와 오늘 남은 횟수를 보여 줍니다.
3. [시작]: 받은 쪽·행·크기, 실패 수, 쉬는 이유가 1초마다 바뀝니다. [멈추기]로 멈춥니다.
4. 끝나면 [쿼리로 열기]나 [분석으로 열기]로 엽니다(연결이 그 파일로 바뀌므로 한 번 더 눌러야 열림).

- **끊겨도 이어 받습니다.** 멈추거나 실패하거나 창을 닫아도, 같은 구성으로 다시 시작하면 받은 쪽은 건너뜁니다. 받는 동안 결과 파일 옆에 `이름.part`가 생겼다가 끝나면 사라집니다.
- 수집은 한 번에 하나만 돌고, 도는 동안 창을 닫으면 닫을지 묻습니다.

### 적재 (DB 테이블, Kafka 토픽)

[적재] 카드에서 받은 결과를 어디에 넣을지 고릅니다. 결과 파일은 늘 만들고, 적재는 그 파일을 조금씩 읽어 넣으므로 행이 많아도 괜찮고 끊겨도 이어 넣습니다.

| 적재할 곳 | 내용 |
|---|---|
| 파일만 | 결과 파일만 만듭니다(기본) |
| DB 테이블 | 내 PC의 DB 파일이나 회사 DB의 테이블에 넣습니다 |
| Kafka 토픽 | 한 행을 메시지 하나(JSON)로 보냅니다 |

**비밀번호는 저장하지 않습니다.** DB·Kafka 비밀번호는 적재할 때마다 입력하고, 시작하면 칸을 비웁니다.

**DB 테이블**

| 넣는 방식 | 동작 |
|---|---|
| 새 테이블 | 새로 만들어 넣습니다. 같은 이름이 있으면 넣지 않습니다 |
| 덧붙이기 | 있는 테이블 끝에 더합니다. 컬럼이 다르면 무엇이 다른지 알려 줍니다 |
| 바꾸기 | 이 프로그램이 만든 테이블만 통째로 바꿉니다. 중간에 실패하면 원래대로 되돌립니다 |

- [확인]으로 넣기 전에 테이블이 있는지, 컬럼이 맞는지 봅니다.
- 덧붙이기에서 키 컬럼(예: `주문번호`)을 넣으면 이미 있는 것은 건너뜁니다(중복 방지). 이 확인 때문에 DB에 조회가 더 나갑니다.
- **[적재 ID 컬럼 넣기]**: 행마다 `_ibis_load_id`에 이번 적재 번호를 넣습니다. 나중에 [업로드 기록](#업로드-기록)에서 이 적재분만 정확히 지울 수 있습니다. 덧붙이기·바꾸기라면 테이블에도 이 컬럼이 있어야 합니다.
- 쿼리·분석에서 같은 DB 파일을 열어 두었으면 적재하지 않습니다(그 연결을 먼저 끊으세요).
- 다른 테이블과 데이터는 건드리지 않습니다.

**Kafka 토픽**

- 보낼 곳(서버 주소, 토픽, 보안 방식, 아이디, CA 인증서 경로)을 등록해 두고 고릅니다. 비밀번호는 등록하지 않습니다.
- [접속 확인]은 메시지를 보내지 않고 접속과 토픽만 확인합니다.
- 메시지 키로 쓸 컬럼을 고를 수 있습니다.

**넣는 단위와 속도**

| 칸 | 뜻 |
|---|---|
| 넣는 단위 | 묶음(기본): 정한 행 수씩. 한 건씩: 한 행씩(느림) |
| 묶음 행 수 | 100~1,000,000(기본 10,000) |
| 간격(초) | 묶음 사이에 쉬는 시간 |
| 다시 시도 | 실패한 묶음을 다시 넣는 횟수 |

적재가 실패해도 결과 파일은 남습니다. [적재만 다시]를 누르면 다시 받지 않고 넣은 다음부터 이어 넣습니다.

### 업로드 기록

[업로드 기록] 카드에는 저장한 파일과, DB·Kafka에 넣은 것이 한 번마다 남습니다. **나중에 "그때 넣은 것만 지워야 할 때" 바로 찾기 위한 장부**입니다. [연동](integrations.md#연동) 화면의 [업로드 기록 보기]로도 엽니다.

![업로드 기록](screen-uploads.png)

| 남는 것 | 예 |
|---|---|
| 언제 | 10-20 09:12 (시작·끝) |
| 어디에 | `warehouse.duckdb · orders`, `로컬 Kafka · shop.events` |
| 어떤 파일에서 | `orders_1020.parquet` |
| 얼마나 | 1,300행, 793 KB |
| 범위 | 적재 ID, 키 컬럼의 처음~끝 값, Kafka는 파티션마다 메시지 번호(offset) 처음~끝 |
| 결과 | 끝, 일부, 실패, 멈춤, 이어 넣었는지 |

- 종류와 찾기 칸(파일·테이블·토픽·적재 ID)으로 거릅니다.
- 줄을 누르면 전체 경로·대상·범위와 **지울 때 쓸 명령**을 보여 줍니다. **프로그램은 지우지 않습니다.** 명령을 확인하고 직접(또는 DB 담당자가) 실행하세요.

| 경우 | 보여 주는 명령 |
|---|---|
| DB, 적재 ID 있음 | `DELETE … WHERE "_ibis_load_id" = '…'` → 그 적재분만 정확히 |
| DB, 새로 만든 테이블 | `DROP TABLE …` → 테이블째 |
| DB, 키만 있음 | 키 처음~끝으로 고르는 `DELETE` → 그 범위의 다른 행도 지워질 수 있다는 주의와 함께 |
| Kafka | 지우기 도구에 쓸 내용. Kafka는 중간만 골라 지울 수 없어 그 앞 메시지까지 지워진다는 주의와 함께 |
| 파일 | 파일 경로 |

- [목록에서 빼기]는 장부에서 줄만 지우고 데이터는 그대로 둡니다.
- 2,000건까지 남기고, 넘으면 오래된 것부터 지웁니다. 비밀번호는 남기지 않습니다.

### 예약 실행

저장한 수집 구성을 정한 때에 저절로 돌립니다. [예약] 카드에서 구성·주기·실행 방식을 정하고 [예약 저장]을 누릅니다.

| 주기 | 예 |
|---|---|
| 매일 | 매일 09:00 |
| 매주 | 월·수·금 09:00 |
| N분마다 | 60분마다(5~1,440분) |

| 실행 방식 | 동작 |
|---|---|
| 프로그램이 켜져 있는 동안 실행 | 프로그램이 켜져 있을 때만 돕니다 |
| Windows 예약 작업으로 등록 | 프로그램을 꺼 두어도 Windows가 정한 때에 창 없이 돌립니다 |

- 예약은 **저장한** 구성으로 돕니다. 구성을 고쳤으면 다시 저장하세요.
- **비밀번호가 필요한 적재(회사 DB 계정, Kafka 비밀번호)는 예약할 수 없습니다.** 비밀번호를 저장하지 않기 때문입니다. API 키는 env 파일에서 읽으므로 됩니다.
- [지금 실행]은 예약처럼 한 번 돌리고 기록합니다.
- 같은 구성이 동시에 두 번 돌지 않습니다.

**Windows 예약 작업**: 작업 스케줄러의 `\ibis_search\` 폴더에만 만들고, 관리자 권한 없이 로그온해 있을 때만 돕니다. PC가 꺼져 있었으면 켜진 뒤 한 번 돕니다. exe를 다른 폴더로 옮겼다면 경고가 나오니 [다시 등록]을 누르세요.

**실행 기록과 알림**

- [실행 기록]에 언제·어떻게 돌았는지, 결과(끝·실패·건너뜀), 행 수가 최근 200개까지 남습니다.
- 창 없이 돈 실행이 실패했으면 다음에 수집 화면을 열 때 "확인하지 않은 실패 N건"이 나옵니다.
- 예약마다 [보낼 곳](integrations.md#다른-앱으로-보내기)을 고르면 실패할 때(또는 늘) Slack 등으로 알려 줍니다.
