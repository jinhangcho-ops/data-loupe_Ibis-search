# 좌표 분석

위도·경도가 든 자료를 거리·반경·격자로 보고, GeoJSON 영역과 이어 지도 카드로 그립니다. 좌표 기능은 처음 쓸 때만 올라오고, 데이터 값은 밖으로 보내지 않습니다(지도 배경을 켠 때만 보는 범위가 지도 서버로 요청됩니다. 아래 참고).

## GeoJSON 연결

폴더 연결에서 `.geojson` 파일(그리고 FeatureCollection인 `.json`)을 고르면 파일마다 표 하나가 됩니다. Feature 하나가 한 행입니다.

| 컬럼 | 내용 |
|---|---|
| 속성 이름들 | GeoJSON의 properties가 그대로 컬럼이 됩니다. 중첩 값은 JSON 글자 |
| `geom_type` | Point, LineString, Polygon, MultiPolygon … |
| `center_lon` `center_lat` | 중심(폴리곤은 구멍을 뺀 면적 무게중심, 점·선은 꼭짓점 평균) |
| `min_lon` `min_lat` `max_lon` `max_lat` | 범위 상자(경도는 -180~180. 날짜 변경선을 넘는 도형은 `min_lon`이 `max_lon`보다 큼, 예: 178·-179. 0~360으로 적힌 경도 파일은 그대로 둔다) |
| `geometry` | 도형 원본(JSON 글자) |

파일의 `crs`가 WGS84가 아니면(예: EPSG:5179) 경도·위도로 바꾼 값을 둡니다. 속성 이름이 위 컬럼과 같으면 `_속성`을 붙입니다.

## 좌표 함수와 조건

함수 사전의 **좌표** 묶음이고, 쿼리의 계산 줄·전처리 계산 컬럼·문장에서 씁니다. 식은 sin·cos 같은 기본 수식이라 원격 DB에서도 DB 안에서 계산됩니다.

- `haversine(위도, 경도, 상대위도, 상대경도)`: 두 점의 거리(km). 상대 점은 숫자 또는 다른 컬럼입니다.
- `within_km`, `in_box`: 반경 안·범위 상자 안이면 참(경계 포함).
- `grid_id(위도, 경도, 칸크기)`: 칸 크기는 도 단위입니다(0.01 = 약 1.1km). `grid_lat`, `grid_lon`은 칸 중심입니다.

조건 줄로는 이렇게 씁니다.

```
near 위도컬럼 경도컬럼 기준위도 기준경도 반경km     예: near lat lon 37.5665 126.978 5
box 위도컬럼 경도컬럼 최소위도 최소경도 최대위도 최대경도
```

최소 경도가 최대 경도보다 크면 날짜 변경선을 가로지르는 상자로 봅니다.

## 전처리의 좌표 단계 (이 PC에서 계산)

전처리 화면 ④ 새 컬럼의 **좌표** 칸에서 단계를 더합니다. 서로 다른 좌표마다 한 번만 계산하고 결과를 새 컬럼으로 붙이므로 같은 좌표의 행은 같은 값이 붙습니다.

- **TM 좌표 → 경도·위도**: x·y 컬럼과 좌표계를 고릅니다.
- **가장 가까운 지점**: 지점 목록 테이블(위도·경도·이름 컬럼)에서 가장 가까운 행의 이름과 거리(km)를 붙입니다. 지점이 많으면 격자로 후보를 줄입니다.
- **들어 있는 영역**: GeoJSON을 연결한 영역 테이블(또는 GeoJSON 파일 경로)의 어느 폴리곤에 드는지 찾아, 고른 영역 컬럼을 붙입니다. 구멍은 밖이고 경계 위는 안입니다. 여러 영역에 걸치면 먼저 나온 영역입니다.

원격 DB는 기존 규칙을 따릅니다. 처리 용량을 먼저 확인하고, 지점·영역 테이블은 쓸 컬럼만 받으며, 계산은 이 PC의 작업 사본에서 합니다.

## 좌표계 고르는 법

컬럼 값이 1,000보다 큰 미터 단위 숫자면 TM 좌표입니다. 화면이 값 범위로 맞을 만한 좌표계를 추천합니다(변환 결과가 한국 안에 떨어지는 것만). 자료 설명에 좌표계가 있으면 그것을 우선하세요.

| EPSG | 이름 | 주로 쓰이는 곳 |
|---|---|---|
| 5179 | UTM-K | 전국 한 장. 지도 서비스·최근 공공데이터(기본값) |
| 5186 | 중부원점 2010 | 서울·경기·충청·전라 지역 최신 자료 |
| 5185 / 5187 / 5188 | 서부·동부·동해원점 2010 | 해당 지역 최신 자료 |
| 5174 | 중부원점(Bessel) | 옛 지적도·옛 공공데이터 |
| 5181 | 중부원점(KGD2002) | 옛 표준 자료 |

잘못 고르면 결과가 수십 km에서 수 m까지 어긋나므로 미리보기의 경도·위도가 맞는 곳인지 확인하세요. 5174는 다른 좌표계와 약 300m 차이가 납니다.

## 좌표 컬럼 자동 인식

전처리에서 테이블을 열면 통계를 낸 뒤 이름(lat·lng·lon·latitude·longitude·위도·경도·x·y)과 값 범위로 좌표 컬럼을 알려 줍니다. 위도가 ±90, 경도가 ±180을 벗어나면 이유와 함께 경고합니다(바뀐 컬럼, 미터 단위 등).

## 지도 카드

대시보드 카드 모음의 **지도**입니다. 영역 경계를 SVG 한 장으로 그리고, 점을 찍고, 영역별 값으로 색칠합니다(값이 클수록 진한 색, 카드 색 설정에서 영역마다 색을 따로 정할 수 있습니다). 확대·이동은 없고 데이터 범위에 맞춘 고정 지도(웹 메르카토르)입니다.

- 영역: GeoJSON을 연결한 테이블이나 GeoJSON 파일 경로, 이름 컬럼, 도형 컬럼(기본 `geometry`).
- 점: 위도·경도 컬럼. 영역별 값은 점의 개수, 또는 값 컬럼의 합계·평균·최소·최대입니다. 영역 테이블에 값 컬럼이 있으면 그것으로 바로 칠할 수도 있습니다.
- 카드 크기 때문에 꼭짓점은 6,000개 안팎, 점은 2,000개까지만 저장합니다. 줄이면 카드 아래에 알립니다.

### 지도 배경(OpenStreetMap)을 켜면

기본은 **꺼짐**이라 경계만 그리고 네트워크 요청이 없습니다. 카드 설정에서 켜면 지도 범위에 맞는 줌의 타일 그림(최대 16장)을 `https://tile.openstreetmap.org/{줌}/{x}/{y}.png`에서 받아 경계 뒤에 깔고 "© OpenStreetMap contributors"를 적습니다.

- 요청되는 것: 보는 지도 범위의 타일 번호(줌, x, y)와 이 PC의 IP, 브라우저 정보입니다. 영역 이름·값·점의 위치 같은 데이터 값은 보내지 않습니다. 다만 타일 번호로 대략 어느 지역을 보는지는 알 수 있습니다.
- 앱은 이 주소의 그림만 허용합니다. 다른 외부 주소는 막혀 있습니다.
- 인터넷이 없거나 받지 못한 타일은 빠지고 경계만 보입니다.
- 대시보드를 PNG·PDF로 내보낼 때도 타일이 담깁니다(내보내는 순간 타일을 한 번 더 받아 넣습니다. 받지 못한 타일은 빠집니다).

## 문장 틀

쿼리 화면의 문장에 세 틀이 있습니다: 영역별 값, 기준점 반경 안의 값, 격자별 값. 영역 이름 컬럼은 위 전처리의 **들어 있는 영역**으로 만듭니다.
