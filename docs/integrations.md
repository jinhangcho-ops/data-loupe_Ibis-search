## 연동

위쪽의 [연동]에서 다른 앱·서비스와 잇는 곳을 한데 봅니다. 서비스마다 하는 일이 다릅니다.

![연동 화면](screen-integrations.png)

| 서비스 | 하는 일 | 설정 |
|---|---|---|
| Slack, Notion, 웹훅 | 보내기: 알림·집계 표·차트 | [보낼 곳 관리](#보낼-곳-등록) |
| Slack 봇 | 받기: `/ibis` 명령에 답하기 | [Slack 봇](#slack-봇-받기) |
| Google Analytics 4 | 가져오기: 보고서를 Parquet 파일로 | 아래 |
| LLM | 묻기: 질문으로 SQL 만들기 | [질문으로 SQL 만들기](query.md#질문으로-sql-만들기) |

카드마다 지금 상태(등록 수, 켜짐, 설정 안 됨)가 보입니다. 새 서비스는 프로그램의 `adapters/` 폴더에 어댑터 파일 하나를 더해 붙입니다(보내기 어댑터는 보낼 곳 종류에 바로 나옵니다).

### Google Analytics 4 가져오기

GA4 Data API로 보고서를 받아 Parquet 파일로 저장하고, [쿼리로 열기]로 바로 탐색합니다.

**준비**

1. Google Cloud에서 서비스 계정을 만들고 키(JSON)를 받습니다. 프로젝트에서 Google Analytics Data API를 켭니다.
2. GA4의 관리 → 속성 액세스 관리에 그 서비스 계정 이메일을 [뷰어]로 추가합니다.
3. 속성 ID(관리 → 속성 설정, 숫자)를 확인합니다.

**쓰기**

1. 서비스 계정 JSON 경로, 속성 ID, 기간(`YYYY-MM-DD`, `today`, `yesterday`, `28daysAgo`처럼), 측정기준(예: `date, country`, 9개까지), 측정항목(예: `activeUsers, sessions`, 10개까지), 저장할 파일(.parquet)을 넣고 [저장]합니다.
2. [연동 확인]은 보고서를 받지 않고 인증과 속성 접근만 확인합니다.
3. [가져오기]는 보고서 전체를 받아 파일로 저장합니다. 같은 이름의 파일이 있으면 덮어쓰지 않습니다. 200만 행이 넘으면 받지 않으니 기간이나 측정기준을 줄이세요.

- 측정기준은 글자, 측정항목은 정수·실수 컬럼이 됩니다.
- 서비스 계정 JSON은 경로만 저장합니다. 그 안의 개인 키는 그 파일에만 있고, 접근 토큰(1시간)은 저장하지 않습니다.
- 저장한 파일은 [업로드 기록](collect.md#업로드-기록)에 남습니다.

## 다른 앱으로 보내기

오래 걸린 작업이 끝났다는 알림이나 집계 표, 차트를 Slack·Notion·웹훅으로 보냅니다. 보낼 곳을 먼저 등록해 두고 씁니다. 등록하지 않으면 프로그램은 바깥으로 아무것도 보내지 않습니다. 위쪽 줄의 [보낼 곳]이나 [연동](#연동) 화면의 [보낼 곳 관리]로 엽니다.

### 보낼 곳 등록

위쪽 줄 오른쪽의 [보낼 곳]을 누르면 패널이 열립니다. 이름을 붙이고 종류와 비밀 값 보관 방식을 고른 뒤 그 종류의 칸을 채우고 [저장]합니다.

- [연동 확인]은 메시지를 보내지 않고 확인합니다. Slack은 토큰이 맞는지(워크스페이스·봇 이름)와, 권한(`channels:read`)이 있으면 채널과 봇이 그 채널에 들어 있는지까지 봅니다. 웹훅은 보내 보지 않고는 알 수 없어 본문 틀의 모양만 봅니다.
- [시험 보내기]로 실제로 도착하는지 확인합니다.

| 종류 | 채울 것 | 보낼 수 있는 것 |
|---|---|---|
| Slack | 봇 토큰, 채널 ID | 글, 그림 |
| Notion | 통합 토큰, 페이지 주소나 ID | 글과 표(페이지 끝에 덧붙임). 그림은 보내지 않음 |
| 웹훅(주소로 보내기) | 주소, 본문 종류, 본문 틀 | 글과 표. 그림은 본문 틀의 `{그림}` 자리에 글자(base64)로 |

- 30개까지 등록합니다.

**비밀 값(토큰·주소) 보관 방식**

보낼 곳마다 고릅니다. 어느 방식이든 화면에 값을 다시 보여 주지 않고, 바꾸려면 새로 입력합니다.

| 방식 | 어디에 두나 | 알아 둘 점 |
|---|---|---|
| 암호화해 저장 | 설정 파일에 Windows가 지금 로그인한 계정으로만 풀 수 있게 암호화해서 | 다른 PC나 다른 계정으로 파일을 옮기면 다시 입력해야 합니다 |
| 이번 실행 동안만 | 메모리에만. 파일에는 남지 않습니다 | 프로그램을 다시 켜면 다시 입력해야 합니다. 창 없이 도는 예약 실행에서는 쓸 수 없습니다 |
| 환경변수 | 프로그램을 띄우는 환경의 환경변수. 파일에는 변수 이름만 남습니다 | 칸에는 값이 아니라 변수 이름(예: `IBIS_SLACK_TOKEN`)을 넣습니다. 그 변수가 없으면 보내지 않고 알려 줍니다 |

예전 버전에서 저장한 보낼 곳은 "암호화해 저장"으로 그대로 씁니다.

**Slack 준비**

1. Slack에서 앱을 만들고 Bot Token Scopes에 `chat:write`와 `files:write`를 넣은 뒤 워크스페이스에 설치합니다.
2. 보낼 채널에 그 앱(봇)을 초대합니다.
3. `xoxb-`로 시작하는 봇 토큰과 채널 ID(`C`로 시작. 채널 정보 맨 아래에 있습니다)를 넣습니다.

**Notion 준비**

1. Notion의 설정 → 연결 → 통합 개발에서 내부 통합을 만들고 토큰(`ntn_` 또는 `secret_`)을 받습니다.
2. 보낼 페이지의 [⋯] → 연결에 그 통합을 추가합니다.
3. 페이지 주소(또는 끝의 32자리 ID)를 넣습니다. [연동 확인]으로 페이지를 읽을 수 있는지 봅니다.

보낼 때마다 페이지 끝에 제목, 내용, 행 수·걸린 시간, 표(코드 블록)가 덧붙습니다.

**웹훅의 본문**

주소는 `https://`로 시작해야 합니다. 본문 종류(JSON, 글자, 폼)를 고르고 본문 틀을 직접 씁니다. 틀에는 아래 자리를 넣을 수 있고, 보낼 때 값으로 바뀝니다.

| 자리 | 들어가는 값 |
|---|---|
| `{제목}` | 무엇을 보내는지 (예: 집계, 검색이 끝났습니다) |
| `{내용}` | 테이블 이름 등 |
| `{행수}` | 행 수 |
| `{걸린시간}` | 걸린 시간 (예: 1분 23초) |
| `{표}` | 표를 글자로 바꾼 것. 50행까지 |
| `{그림}` | 그림(PNG)을 base64 글자로 바꾼 것. 없으면 빈 글자 |

- [기본 틀]에서 일반 JSON, Teams, Discord, 글자용 틀을 골라 시작할 수 있습니다. 받는 쪽이 요구하는 모양에 맞게 고쳐 씁니다.
- 값 안의 따옴표나 줄바꿈은 본문 종류에 맞게 처리해 넣습니다. JSON은 값을 채운 결과가 JSON으로 읽히지 않으면 보내지 않습니다.
- 틀은 보낼 곳과 함께 저장됩니다.

### Slack 봇 (받기)

Slack에서 `/ibis` 명령으로 저장한 검색과 지표를 물어보면 이 프로그램이 답합니다. 이 프로그램이 켜져 있고 데이터에 연결돼 있을 때만 답합니다.

**Slack 준비**

1. Slack 앱 설정에서 Socket Mode를 켭니다. 이때 만드는 앱 토큰(`xapp-`, `connections:write`)을 적어 둡니다. Socket Mode는 이 PC에서 Slack으로 나가는 연결만 써서, 열어 둘 포트나 공개 주소가 필요 없습니다.
2. Slash Commands에 `/ibis`를 만듭니다.
3. Bot Token Scopes에 `commands`를 넣고 워크스페이스에 설치한 뒤 봇 토큰(`xoxb-`)을 받습니다.
4. 명령을 쓸 사람의 Slack 사용자 ID(`U`로 시작. 프로필의 [⋮] → [멤버 ID 복사])를 확인합니다.

**프로그램 설정**

[보낼 곳] 패널 아래의 "Slack 봇 (받기)"에서:

1. 토큰 보관 방식을 고르고(보낼 곳과 같은 세 방식) 봇 토큰과 앱 토큰을 넣습니다.
2. 허용할 사용자 ID를 넣습니다. 비어 있으면 봇을 켤 수 없습니다. 허용할 채널 ID도 넣으면 그 채널에서만 받습니다(비우면 허용한 사용자라면 어느 채널에서든).
3. [저장] → [연동 확인]으로 두 토큰을 확인하고 → [봇 시작]을 누릅니다. [봇 멈춤]을 누르거나 프로그램을 닫으면 멈춥니다.

**명령**

| 명령 | 답 |
|---|---|
| `/ibis` 또는 `/ibis 도움` | 쓸 수 있는 명령 |
| `/ibis 지표` | 지표 목록(많이 쓴 순) |
| `/ibis 지표 CTR 검색="이번 달"` | 저장한 검색 "이번 달"의 테이블·조건 위에서 지표 값 |
| `/ibis 지표 CTR 검색="이번 달" 나누기=day` | 그 컬럼의 값마다 지표 값(표) |
| `/ibis 검색` | 저장한 검색 목록(많이 쓴 순) |
| `/ibis 검색 "이번 달" 행=10` | 저장한 검색의 행 수와 앞 행들(기본 20행, 50행까지) |
| `/ibis 질문 지난달 매장별 매출 합계` | [LLM](query.md#질문으로-sql-만들기)으로 만든 SQL. 실행하지 않습니다(프로그램의 SQL 탭에서 확인하고 실행) |

- 값에 빈칸이 있으면 따옴표로 감쌉니다.
- 답은 물어본 사람에게만 보입니다.
- 저장해 둔 검색과 지표만 씁니다. SQL을 직접 실행하거나 데이터를 바꾸는 명령은 없습니다.
- 허용하지 않은 사용자·채널에서 온 명령에는 쓸 수 없다고만 답합니다. 패널에 최근 요청 20개(거부 포함)가 보입니다(메모리에만, 끄면 사라짐).
- 프로그램이 다른 작업 중이면 끝날 때까지(60초까지) 기다렸다가 답합니다.

### 끝나면 알림

보낼 곳의 [오래 걸린 작업이 끝나면 여기로 알림]을 켜 두면, 정한 시간(기본 30초, 5초에서 3,600초 사이) 이상 걸린 작업이 끝났을 때 알립니다. 보내는 것은 작업 종류, 테이블 이름, 행 수, 걸린 시간이고 데이터의 값은 보내지 않습니다. 취소했거나 오류로 끝난 작업은 알리지 않습니다.

### 집계와 차트 보내기

쿼리 화면의 집계 탭과 차트 탭에서 보낼 곳을 고르고 [보내기]를 누릅니다. 버튼에 보낼 곳과 보낼 것이 표시되고, 한 번 더 눌러야 보냅니다.

- 집계: 집계 표를 글자와 그림으로 보냅니다.
- 차트: 차트의 값(표)과 차트 그림을 보냅니다.
